# Automated Vocab Flashcard Generation — Cloud Workflow Documentation

## 1) Workflow overview

This n8n workflow automates the creation of language learning flashcards from raw PDF documents (e.g., word lists, textbooks). It ingests a PDF, extracts vocabulary, checks for duplicates against PostgreSQL, enriches words with definitions and CEFR levels using AI, generates a custom illustration for each word, uploads it to MinIO, and saves the final flashcard data to PostgreSQL.

### Key features

- **PDF Ingestion:** Extract text directly from uploaded files.
- **Duplicate Prevention:** Checks existing PostgreSQL records to ensure only new words are processed.
- **AI Enrichment:** Uses Google Gemini to generate definitions, example sentences, parts of speech, and difficulty labels (CEFR).
- **AI Illustration:** Generates custom vector-style illustrations for each vocabulary word.
- **Self-hosted Storage:** Stores text data in PostgreSQL and image assets in MinIO.

## 4) Node documentation

### Phase 1: Ingestion and initial extraction

#### Webhook — Upload Vocabulary PDF

- **Type:** Webhook
- **Purpose:** Entry point. Receives a POST request containing the PDF file from the CMS backend.
- **Endpoint:** Auto-generated by n8n (e.g., `https://<n8n-coolify-domain>/webhook/<id>`)
- **Method:** POST

> After deploying n8n and activating the workflow, copy the production webhook URL and set it as `N8N_WEBHOOK_URL` in the CMS backend's Coolify environment variables.

#### Extract Text from PDF

- **Type:** Extract from PDF
- **Purpose:** Parses the binary PDF data and converts it into raw text.

#### Get Words (AI Agent)

- **Type:** AI Agent
- **Purpose:** Scans raw text to identify and extract vocabulary words.
- **Configuration:** Prompt instructs extraction of the first 10 words per run (adjustable).
- **Attached nodes:** Gemini Model + Parse Words JSON.

#### Split Out

- **Type:** Split Out
- **Purpose:** Takes the word array and splits into individual items for one-by-one processing.

### Phase 2: Deduplication

#### Get all words from PostgreSQL

- **Type:** PostgreSQL
- **Operation:** Execute Query (`SELECT word FROM vocab_flashcards`)
- **Purpose:** Fetches existing words to prevent duplicate flashcard creation.

#### Merge

- **Type:** Merge
- **Mode:** Keep Non-Matches
- **Purpose:** Compares incoming words against existing words. Keeps only new words.

### Phase 3: AI enrichment

#### Generate Words, Meanings, Labels (AI Agent)

- **Type:** AI Agent
- **Purpose:** Takes each filtered word and generates: CEFR Level, Definition, Example sentence, Part of speech, Category, Unique ID.
- **Attached nodes:** Gemini Model + Parse Words JSON (ensures strict JSON output).

#### Split Out

- **Type:** Split Out
- **Purpose:** Splits enriched JSON array into individual items for parallel text/image processing.

### Phase 4: Text data storage

#### Edit Fields

- **Type:** Edit Fields
- **Purpose:** Maps the AI Agent's JSON structure into flat fields: `label`, `pos`, `category`, `exampleSentence`, `definition`, `word`.

#### Insert flashcard into PostgreSQL

- **Type:** PostgreSQL
- **Operation:** Insert
- **Table:** `vocab_flashcards`
- **On conflict:** Do nothing (skip duplicates)
- **Column mapping:** `word`, `label`, `pos`, `category`, `example_sentence`, `definition`

### Phase 5: Visual asset generation and storage

#### Generate Flashcard Illustration

- **Type:** Google Gemini
- **Model:** `models/gemini-2.5-flash-image`
- **Prompt:** Generates a flat vector illustration based on the example sentence.
- **Style:** Friendly, educational corporate vector art with clean thick outlines and flat pastel colors.
- **Constraint:** No text, words, or letters in the image.

#### Upload illustration to MinIO

- **Type:** S3 (configured to point at MinIO)
- **Bucket:** Read from `MINIO_BUCKET` environment variable
- **Object name:** `flashcards/<word>.png`
- **ACL:** Public read

#### Build Image URL

- **Type:** Edit Fields
- **Purpose:** Constructs the public URL: `<MINIO_PUBLIC_URL>/<MINIO_BUCKET>/flashcards/<word>.png`

#### Update image URL in PostgreSQL

- **Type:** PostgreSQL
- **Operation:** Update
- **Table:** `vocab_flashcards`
- **Sets:** `media_link` to the constructed URL
- **Where:** `word` matches

## 5) Deployment on Coolify (Lightsail)

### Creating the n8n application

1. In Coolify, create a new application:
   - **Source:** Docker image `n8nio/n8n`
   - **Port:** `5678`
2. Add a persistent volume mounted at `/home/node/.n8n`.
3. Set environment variables:

| Variable | Value |
|---|---|
| `N8N_PROTOCOL` | `https` |
| `N8N_HOST` | Your n8n Coolify domain (without `https://`) |
| `WEBHOOK_URL` | `https://<your-n8n-coolify-domain>` |
| `N8N_ENCRYPTION_KEY` | `openssl rand -hex 32` |
| `GENERIC_TIMEZONE` | `America/New_York` (or your timezone) |
| `N8N_SECURE_COOKIE` | `true` |
| `MINIO_BUCKET` | `flashcards` |
| `MINIO_PUBLIC_URL` | `https://<minio-coolify-domain>` |

4. Deploy and create an admin account.

### Importing the workflow

1. In n8n, go to **Workflows** > **Import from File**.
2. Upload `Automated Vocab Flashcard Generation n8n Workflow (PostgreSQL + MinIO).json`.

### Configuring credentials in n8n

Create the following credentials inside n8n's credential manager:

1. **Google Gemini (PaLM) API** — enter your Gemini API key.
2. **PostgreSQL** — enter host, port, database, user, password from your Coolify PostgreSQL service.
3. **S3** — configure as:
   - **Endpoint:** MinIO API URL (e.g., `https://<minio-coolify-domain>`)
   - **Region:** `us-east-1` (any value works for MinIO)
   - **Access Key:** your `MINIO_ROOT_USER`
   - **Secret Key:** your `MINIO_ROOT_PASSWORD`
   - **Force Path Style:** enabled

Then reconnect each node to the appropriate credential.

### Activating the workflow

1. Toggle the workflow to **Active**.
2. Click the webhook node and copy the **Production URL**.
3. Set this URL as `N8N_WEBHOOK_URL` in the CMS backend's Coolify environment variables.

## 7) Monitoring and maintenance

### Execution history

n8n stores execution history in its persistent volume. View past runs, inspect node outputs, and debug failures from the n8n UI.

### Common issues

| Problem | Check |
|---|---|
| Webhook not receiving files | Workflow activated? `N8N_WEBHOOK_URL` in backend matches production URL? |
| PostgreSQL writes failing | Credentials correct in n8n? Table `vocab_flashcards` exists? |
| Image generation failing | Gemini API key valid? Quota not exhausted? |
| MinIO upload failing | S3 credential configured with correct endpoint + force path style? Bucket exists? |
| Duplicate words appearing | Merge node set to "Keep Non-Matches"? PostgreSQL query returns results? |
| Images not loading | MinIO bucket access policy set to public? `MINIO_PUBLIC_URL` correct? |

### Backups

- n8n persistent volume stores workflows, credentials, and execution history — back it up.
- PostgreSQL: configure automated backups in Coolify.
- MinIO: back up the `/data` volume.

## 8) Integration with CMS backend

The CMS backend (Express server) connects to this workflow via the webhook URL.

**Request format:**
- `POST` to the webhook URL
- Body: raw PDF binary
- Headers:
  - `Content-Type`: the file's MIME type
  - `Content-Disposition`: `attachment; filename="<original-filename>"`

**Response:** n8n does not return flashcard data to the backend. The backend acknowledges the upload, and the frontend later fetches results from PostgreSQL via `GET /api/flashcards`.
